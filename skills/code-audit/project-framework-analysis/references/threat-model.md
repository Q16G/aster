# 全局威胁模型细则（threat-model = 攻击面映射）

> 五张模型之一「全局威胁模型」的细则。本模型**综合前四张模型**（项目架构 / 入口点 / 认证与权限 / 业务），把它们的事实汇总成统一的**攻击面映射**——「每个攻击面单元 × 每个结构上可能成立的漏洞维度」的全量清单，供下游各维度**按接口逐一取用、逐一全测**。
>
> **红线**：本模型只供信息，**不排优先级、不做 in-scope / out 取舍、不指挥先测后测**。它不产生前四张之外的新事实，只做一次汇总视图。给出的每个接口的每个可能维度，下游都要测——欠覆盖比重复更糟。

## 建模两步

### 1. 攻击面清单

从前四张模型汇聚攻击面单元，每个单元至少含：

- 入口点（来自入口点模型：路由 + 参数 + 鉴权要求 + 信任边界）。
- 承载的业务语义与高价值资产（来自业务模型）。
- 触达的 sink / 框架封装位置（来自架构模型）。
- 可达身份（来自认证与权限模型：匿名 / 用户 / 管理员 / 跨租户）。

**穷举不省略**：攻击面清单必须覆盖入口点模型枚举出的全部端点，缺一个 = 下游对该端点整类维度失去锚点。

### 2. 攻击面 × 漏洞维度适用性映射

对每个攻击面单元，登记**哪些漏洞维度在其上结构性成立**——结合该入口的参数形态、sink 语义、业务不变量，逐维度陈述事实：

- 结构型（RCE / SQLi / XXE / SSRF / 命令注入 / 路径穿越 / 反序列化 / 模板注入）：是否有对应 sink 封装在可达路径上。
- 语义型（水平 / 垂直越权 / IDOR / 逻辑 / 状态机绕过 / RBAC / 竞态）：是否触及业务不变量与归属字段。
- 配置 / 依赖型（安全头 / CORS / 硬编码 / 已知 CVE 依赖）：架构模型标注的配置与闭源依赖位置。

**映射是信息，不是取舍**：`rationale` 只陈述「该维度在此接口成立的事实依据」，让下游据此**逐一全测**每一个登记的（接口 × 维度）。

**"结构上不可能成立"的记录方式**：某维度在某接口结构上确实不可能成立（如无参数、无 DB sink 的 health 端点无 SQLi），可作**事实陈述**记录（`rationale` 写明依据），但——
- 不表述为 `out-of-scope` / `跳过` / `不测`；
- 不得成为下游省略该接口其他维度的依据；
- 不设 `in_scope` 布尔、不设 `priority`。是否真的不可测由下游各维度 skill 独立判断，本模型只提供事实线索。

## 输出用途

攻击面映射是下游的**信息底图**——回答「这个接口上可能存在哪些维度的漏洞、依据是什么事实」，让下游对每个接口的每个登记维度**逐一全测**。它不回答「先测哪个、跳过哪个、按什么顺序」——那是下游自己的事，本模型不干预。

## 产物落库

写入 `shared/models/threat-model.md`：按攻击面单元组织的全量适用性映射表。

```markdown
## 攻击面 × 漏洞维度适用性映射
| 攻击面(入口/资产) | 可达身份 | 漏洞维度 | rationale(事实依据) |
|------------------|---------|---------|---------------------|
| POST /api/order/refund | user | 业务逻辑-重复退款 | 退款金额来自请求且未见幂等校验(business invariant 唯一性缺口)，触达资金——下游按此接口测该维度 |
| GET /api/user/{id}/profile | user | IDOR-水平越权 | id 用户可控，未见 owner 归属校验(entity_field owner=userId) |
| GET /api/health | anon | SQLi | 结构上不可能成立：无参数、无 DB sink 可达(事实记录，非取舍，不影响该接口其他维度) |
```

`rationale` 必须引用前四张模型的具体事实（entity_field / middleware / invariant / framework_wrap），不写泛化推断，不写优先级、不写取舍。

> 注意：本文件 `references/threat-model.md` 是**建模方法论细则**（怎么建）；运行时产物落 `shared/models/threat-model.md`（建出来的模型）。二者同名不同物。
